## 1. Objetivo y alcance

Se auditó el estado del proyecto en la versión de release `v2.44.3`, la cual incorpora:
1. **HCD-014 (parcial):** Compresión y reducción de peticiones de contexto salientes para Claude, Codex y Herdr, gestión de autorizaciones en `automatic_original_grants`, deduplicación de bloques y transformaciones de peticiones en `adapters/secondary/requestcompression`.

3. **HCD-016:** Corrección de rutas relativas con `~` en `skills.json` hacia rutas absolutas requeridas por `agy 1.4.12`.
4. **HCD-017:** Cierre formal de los hallazgos ADM-01 a ADM-05 detectados en la auditoría del release `v2.43.1`.
5. **HCD-018:** Recuperación de originales en `compression_originals` resiliente a contención en base de datos (`pack retrieve` devuelve el contenido leído aunque la renovación de TTL falle por bloqueo de escritura).

## 2. Metodología y límites

- **Auditoría Defensiva (ADM):** Análisis estático y dinámico enfocado en programación defensiva: validación de entradas no confiables (transcripts, payloads JSON externos), prevención de fugas de recursos/descriptores, concurrencia y carreras de datos (`-race`), comportamiento fail-safe/fail-open de hooks ante caídas o excepciones, y atipicidades en SQLite (transacciones, bloqueos, integridad referencial).
- **Consenso Adversarial (ACR):** Ejecución del protocolo estandarizado en la base de datos de gomemory (`review_start` → `review_submit` [A y B] → `review_consensus` → `review_finalize`).
  - **Revisor A:** Correctitud funcional, contratos de protocolo de hooks, transiciones de estado, idempotencia y regresiones respecto a `v2.43.1`.
  - **Revisor B:** Lente defensiva: saneamiento de cadenas, manejo de rutas (`filepath`), seguridad de subprocesos, manejo de contención en bases de datos y límites de recursos.
  - **Nivel de independencia:** **Parcial / Degradado** (`degraded: same-model`). Ambos roles fueron ejecutados secuencialmente en el mismo entorno de modelo (`gemini-3.8-flash`) manteniendo aislamiento estricto de contexto entre las fases de recolección previas al ledger de consenso.

### Detalle de Hallazgos

#### ADM-06 (C-001) — Comillas dobles en transcript de Antigravity CLI impiden reindexación automática de archivos Go
- **Ubicación:** `adapters/primary/cli/hook_agy.go:121-135` y `adapters/primary/cli/cmd_hook.go:1164`.
- **Severidad:** Baja (Calidad / Rendimiento del grafo de código).
- **Clase de evidencia:** `runtime-observation` / reproducido.
- **Mecanismo del defecto:**
  En sesiones interactivas de Antigravity CLI, las llamadas a herramientas registradas en `transcript.jsonl` contienen cadenas de argumentos serializadas con comillas externas adicionales (ej. `"args":{"Path":"\"/workspace/file.go\""}` o `"CommandLine":"\"go test\""`).
  Al procesar el turno en `hook_agy.go:128-133`:
  ```go
  case call.Args.Path != "":
      files = append(files, call.Args.Path)
  ```
  `call.Args.Path` conserva las comillas dobles literales al inicio y fin de la ruta (`"\"/workspace/file.go\""`).
  Posteriormente, al invocarse el hook `turn-end`, se llama a `reindexTouchedGoFiles`:
  ```go
  if filepath.Ext(f) != ".go" {
      continue
  }
  ```
  Debido a la comilla de cierre, `filepath.Ext("\".../file.go\"")` devuelve `".go\""` (en lugar de `".go"`). La condición se cumple y el archivo es ignorado, omitiendo la actualización incremental del grafo de código (`CodeGraphRepo`) tras ediciones en Antigravity.
- **Impacto:** Las memorias de tipo checkpoint se registran correctamente pero muestran comillas adicionales (`Editó: "path/file.go"`), y el grafo de código no se actualiza automáticamente de forma incremental en turnos de `agy` hasta que se ejecuta una reindexación manual.
- **Propuesta de cierre:**
  En `adapters/primary/cli/hook_agy.go`, sanear los argumentos extrayendo comillas externas con una función auxiliar:
  ```go
  func cleanAgyArg(s string) string {
      s = strings.TrimSpace(s)
      return strings.Trim(s, "\"")
  }
  ```
  Aplicar `cleanAgyArg` a `call.Args.CommandLine` y `call.Args.Path` antes de agregarlos a `commands` y `files`.

---

#### ADM-07 (C-002) — `InspectAgyEntry` condicionado rígidamente a versión exacta 1.4.12
- **Ubicación:** `adapters/primary/setup/agy_setup.go:187, 212-214`.
- **Severidad:** Baja / Informativa (Experiencia de usuario).
- **Clase de evidencia:** `static-analysis` / `contract`.
- **Mecanismo del defecto:**
  `agyCheckedVersion` está fijado como constante `"1.4.12"`. En `InspectAgyEntry`:
  ```go
  case version != agyCheckedVersion:
      ch.State = domain.StateOutdated
      ch.Detail = fmt.Sprintf("agy %q sin comprobar; contrato observado en %s", version, agyCheckedVersion)
  ```
  Cualquier actualización menor de Antigravity CLI (ej. `1.4.13` o `1.5.0`) provocará que `mem doctor` reporte el canal de `agy` como `StateOutdated`, a pesar de que el protocolo de hooks (`SessionStart`, `PreInvocation`, `PreToolUse`, `PostToolUse`, `Stop`) permanezca completamente compatible y operativo.
- **Impacto:** Falsa alarma en diagnósticos rutinarios de `mem doctor` tras actualizaciones del CLI de Gemini/Antigravity.
- **Propuesta de cierre:**
  Permitir compatibilidad de prefijo semántico (ej. `strings.HasPrefix(version, "1.4.")`) o clasificar versiones no verificadas con un estado menos alarmante si los hooks y archivos de configuración están intactos y vigentes.

## 5. Auditoría de Seguridad, Concurrencia y Robustez Defensiva

1. **Gestión de Concurrencia y Deadlocks (HCD-018):**
   - Se validó el cambio en `adapters/secondary/persistence/compression_originals.go:148-164`. La lectura del original se realiza bajo transacción/select; si la actualización de `last_access_at` falla por contención o bloqueo de escritura (`BEGIN IMMEDIATE` de otra sesión), el contenido ya recuperado en memoria se devuelve al cliente sin abortar.
   - La suite de `-race` confirmó ausencia total de carreras en los repositorios de persistencia y usecases.
2. **Fail-Open en Hooks de Agentes:**
   - En `hook_agy.go:197-203`, `agyHookResponse` implementa recuperación ante pánicos (`defer func() { if recover() != nil ... }`) y devuelve invariablemente `agyDefaultResponse` (`{"decision":"allow"}` en herramientas o `{}`), asegurando que un fallo en `gomemory` nunca bloquee el flujo de trabajo del usuario en el agente.
   - El presupuesto global `agyHookBudget` (8s) y `context.WithTimeout` acotan la ejecución de subprocesos.
3. **Inyección de Comandos y Rutas:**
   - En `adapters/secondary/requestcompression/transform.go:57`, el identificador de sesión se escapa rigurosamente con comillas simples POSIX (`strings.ReplaceAll(..., "'", "'\"'\"'")`), impidiendo ataques de interpolación o inyección en sugerencias de recuperación.
   - `requestcompression.eligible` filtra estrictamente caracteres de shell compuestos (`;|&\n`$<>`), previniendo desbordamiento a comandos destructivos o lecturas arbitrarias.
4. **Privacidad de Memorias y Originales Comprimidos:**
   - La tabla `automatic_original_grants` cuenta con integridad referencial (`ON DELETE CASCADE`) y un trigger de respaldo en SQLite (`revoke_automatic_original_grants`) que garantiza la revocación inmediata de permisos si un original es eliminado de `compression_originals`.
