Lo mejor del proyecto: Los Puntos Clave

Por qué gomemory no es un simple volcado de texto sino infraestructura real
1. SQLite Local y Estructurado

La memoria vive fuera del repositorio en ~/.local/share/gomemory (o AppData en Windows). No ensucia el historial de Git con archivos Markdown dispersos. Guarda decisiones, bugs resueltos, arquitecturas y preferencias clasificadas con FTS5 y ranking BM25.

2. Presupuesto de Contexto

Los LLMs tienen límites de ventana y costo. gomemory no inyecta "todo": administra un presupuesto de tokens riguroso (aprox. 3,000–4,200 caracteres al arrancar), comprime salidas gigantescas de herramientas y ofrece compresión reversible con mem pack.

3. Metodología HCD y Verificación

No asume que el código funciona porque el modelo diga "listo". Exige comprobaciones reproducibles, TDD donde se debe ver el fallo previo antes de la corrección (--expect-fail) y aprobación ligada a revisiones Git concretas.

4. Revisión Adversarial: Splash

Para evitar el sesgo de confirmación donde el agente aplaude su propio diseño, gomemory despliega a Splash: un subagente que nace sin memoria ni contexto del proyecto para realizar una auditoría fría e implacable.

Cómo explicárselo a la audiencia:

"Imaginen que gomemory es el 'Flight Recorder' y la libreta de bitácora del proyecto. El agente no improvisa: consulta la base de datos local, recupera las decisiones del equipo y valida con pruebas verificables antes de tocar producción."

El Rol del Usuario: La Especificación en Palabras

El desarrollador es el dueño de la intención, no el mecanógrafo de código
La regla de oro: El usuario define el QUÉ y el POR QUÉ. El agente propone el CÓMO, pero queda restringido por las fronteras del alcance.
Paso Lo que hace el Usuario Lo que ejecuta gomemory
1. Intención Escribe en lenguaje natural el objetivo y el valor de negocio esperado. Inicia la unidad HCD y estructura el documento hcd/HCD-NNN-slug.md.
2. Alcance (Scope) Declara qué está dentro y explícitamente qué queda fuera. Bloquea que el modelo modifique componentes colaterales o asuma tareas extra.
3. Clarificación Responde de 1 a 3 preguntas críticas (Socratica). Resuelve ambigüedades arquitectónicas sin obligar a escribir 20 páginas de especificaciones.
4. Aprobación Revisa el resumen y aprueba con un comando o confirmación verbal. Firma la revisión en el ledger de la base de datos atada al hash exacto de Git.
Tu Guion Verbal:

"Nadie quiere escribir especificaciones interminables en Jira. En gomemory, tu trabajo como dev es decir: 'Quiero este endpoint, con este criterio de éxito, y NO toques el módulo de autenticación existente'. El sistema toma eso, te hace dos preguntas clave para desambiguar, y solo cuando das el visto bueno arranca el motor."

Bajo el Capó: stdio, HTTP y Server-Sent Events (SSE)

Por qué el protocolo local stdio es la elección superior para coding agents

Cuando un agente interactúa mediante el estándar MCP (Model Context Protocol), la forma en que los datos viajan define la seguridad, velocidad y robustez del sistema:

Mecanismo Cómo funciona Ventajas Cuándo se usa
stdio
(Standard I/O)		 El harness lanza mem mcp como subproceso hijo. La comunicación viaja por tuberías directas del SO (stdin / stdout) con JSON-RPC. Sin puertos de red, sin firewalls, sin latencia de socket TCP, muere automáticamente con el padre. Por defecto en gomemory para Claude Code, agy, Codex y OpenCode locales.
HTTP clásico Petición y respuesta tradicional (Request/Response). El cliente envía un POST y el servidor responde cerrando la transacción. Familiar, ampliamente soportado por cualquier proxy o balanceador. Servidores remotos donde no se necesita streaming en tiempo real.
SSE
(Server-Sent Events)		 Canal HTTP persistente (text/event-stream). El cliente abre la conexión y el servidor "empuja" (push) mensajes continuos. Streaming ligero, reconexión automática nativa, sin la sobrecarga de WebSockets. Servidores MCP desacoplados o remotos en la nube que emiten respuestas token por token.
Frase para impresionar a la audiencia:

"¿Por qué usamos stdio en vez de levantar un servidor HTTP local? Porque un socket de red local es una vulnerabilidad innecesaria: expone puertos, compite por recursos y puede quedar huérfano. Con stdio, el agente y gomemory se comunican a través de pipes del kernel de Go. Cero latencia, cero puertos abiertos y aislamiento total."

El Meta-Harness: Eventos del Host vs. Hooks de gomemory

La frontera arquitectónica entre la notificación y el gobierno determinista

Uno de los mayores logros arquitectónicos de gomemory es ser un meta-harness: abstrae las peculiaridades de cada agente mediante una capa neutral.

El Evento (Emitido por el Host)

Es una notificación interna del ciclo de vida del agente: "Inicié sesión" (SessionStart), "El usuario envió un prompt" (UserPromptSubmit) o "Voy a ejecutar una herramienta" (PreToolUse). Depende enteramente de la empresa creadora del agente.

El Hook (Ejecutado por gomemory)

Es el comando ejecutable de Go (mem hook <subcomando>) que atrapa el evento. Traduce el dialecto del host a un contrato neutral, evalúa reglas en menos de 50 ms y decide: inyectar memorias, registrar evidencias o bloquear comandos destructivos.

Flujo en Tiempo de Ejecución
Harness Host (Claude/Codex/agy)  ──[ Dispara Evento: PreToolUse ]──>
  └─> gomemory (`mem hook expand`)
        ├─> hook_dialect.go: Decodifica payload JSON
        ├─> domain/rules.go: ¿El comando contiene 'rm -rf' o toca secretos?
        └─> Veredicto: Exit Code ≠ 0 (Denegado)  ──>  El host cancela la ejecución
Tu Analogía para Explicarlo:

"El Evento es como el timbre de una puerta: el harness dice 'alguien tocó'. El Hook es el guardia de seguridad que abre la puerta, revisa la identificación contra una lista de reglas en milisegundos y decide si te deja pasar o te detiene."

Glosario Técnico para Desarrolladores

Definiciones precisas y analogías cotidianas para responder cualquier pregunta
Harness
El entorno o runtime que envuelve y ejecuta al LLM (ej. Claude Code, Codex, Antigravity, OpenCode). Provee la interfaz de usuario, ejecuta comandos en la terminal y maneja el bucle de herramientas. Analogía: El chasis y tablero del automóvil donde se monta el motor.
Meta-Harness
Una capa arquitectónica superior (gomemory) que se sitúa por encima de múltiples harnesses distintos, estandarizando su memoria, sus hooks y su disciplina operativa para que un proyecto se comporte igual sin importar qué agente uses. Analogía: Un sistema operativo común que corre indistintamente en Macs, PCs o servidores Linux.
Lifecycle Hook
Punto de interceptación donde un programa externo puede inyectar lógica o reglas antes o después de que el agente ejecute una acción crítica. Analogía: Un middleware en Express.js o un Git Hook pre-commit.
MCP (Model Context Protocol)
Estándar abierto de la industria para que los modelos de lenguaje descubran y llamen a herramientas y orígenes de datos locales o remotos usando JSON-RPC. Analogía: El conector USB-C universal para conectar periféricos a la IA.
FTS5 + BM25
Motor de búsqueda de texto completo integrado nativamente en SQLite (Full-Text Search 5) con el algoritmo probabilístico de ranking BM25, garantizando búsquedas léxicas instantáneas sin bases de datos vectoriales pesadas. Analogía: El motor de búsqueda interno de un libro con un índice analítico perfecto.
Token Budgeting
Técnica de gestión estricta del número de tokens enviados en el prompt del sistema para no desperdiciar dinero ni saturar la atención del modelo con información irrelevante. Analogía: Empacar una mochila con peso exacto para no pagar exceso de equipaje en el avión.
HCD (Harness Continual Dev)
Metodología creada por gomemory para guiar el ciclo de vida de una tarea: definición, clarificación, descomposición en tareas atómicas, TDD estricto y verificación empírica. Analogía: El método de doble diamante de diseño combinado con Extreme Programming.
Splash (Subagente Ciego)
Instancia aislada del agente que se invoca deliberadamente sin el contexto de memoria del proyecto para revisar documentos o código de forma completamente imparcial. Analogía: El revisor externo o auditor que no participó en la reunión de diseño para garantizar que la documentación sea autoexplicativa.
Context Pack
Estructura de empaquetado y compresión reversible de fragmentos de código y memoria diseñada para ser rehidratada bajo demanda cuando el agente realmente la necesite. Analogía: Un archivo .zip que solo descomprimes cuando vas a leer el documento.
